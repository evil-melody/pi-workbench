**G4 失败定位（可复现）**：`scripts/visual-check.mjs:418` 初始化 stub 时未声明 `emitted` 字段：

```js
window.__PI_STUB__ = { calls: [], rpcTypes: [], bound: null, ..., listeners: {}, ... }  // 无 emitted
```

而 `scripts/visual-check.mjs:431` 的 `emitPi()` 直接执行：

```js
window.__PI_STUB__.emitted.push(rec.type)  // emitted === undefined → TypeError
```

即：**harness 自身 bug，非 App 崩溃**。根因是 stub 初始化漏字段，修复只需在 `:418` 的字面量里补 `emitted: []`。

## 偏离与说明

1. **`groupIssues` 保留**：`tests/expertDomain.spec.ts` 结构性依赖（记录于 AUDIT-024 行）。
2. **SessionTree 缩进方案**：用 `--row-indent` CSS 变量而非 depth 类绑定——会话树深度无上界，类方案需无限预生成规则，变量方案一格到位。
3. **visual-check.mjs 两轮返工**：AUDIT-001 修复时在模板字符串 `PI_STUB_SCRIPT` 内的注释里误用反引号，两次触发 SyntaxError（`node --check` 暴露），已改单引号/纯文本。教训：往页内注入脚本的模板字面量里禁写反引号。
4. **cargo check 残留 1 条链接器提示**：`ld: __eh_frame section too large` 为 macOS ld + debuginfo 的环境性警告（仅 test profile 出现），非代码问题，基线同样存在，未处理。
5. **守卫判据兼容 `pub async fn`**：`skills_install_from_url` 等 async fn 命令的 `#[tauri::command]` 属性本就不写 `(async)`（Tauri 对 async fn 直接在异步运行时执行），守卫相应接受「属性含 async **或** 声明为 `pub async fn`」两种安全形式，避免把正确写法误杀。
6. **QA Round 1 逃逸补修**：6 个含阻塞 IO 的 sync 命令（mcp_disconnect / library_set_enabled / skills_install / skills_uninstall / role_current / artifacts_open）不在首轮名单内，已补标 async 并收编；修复后 cargo check 零警告、cargo test 183 passed、两条守卫 ok，前端 typecheck/vitest 无连带（283/28 不变）。
